# M11.2 World Model and Chunk Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the protocol 47 block encoding that `pkg/world` stores in memory with interned, version-neutral state handles; make sections immutable so a write swaps a pointer and a snapshot is a pointer copy; and delete the override map that is the world's second source of truth.

**Architecture:** `world.State` is an opaque `uint32` handle minted by a `StateRegistry` built from a `data.Set`. Handles never reach disk or wire: storage holds canonical names and the wire holds each version's own encoding, produced by an `Adapter`. A `Chunk` holds immutable `*Section` pointers and is itself replaced by a compare-and-swap on write, which makes `World.Snapshot` a map copy and makes encoded section bytes cacheable on the section pointer.

**Tech Stack:** Go 1.26.6 via `openserbia/go-flake`, Devbox, Task, `minecraft-protocol` v0.2.0 as a released module, vendored dependencies.

- [ ] **Step 2: Implement**

```go
// State is an opaque handle to a block state. Its numeric value is assigned
// at registry construction and is meaningful only to the process that built
// it. It is never persisted and never put on the wire.
type State uint32

// Properties is a block state's property set, sorted by key. Java 1.8 leaves
// it empty and encodes variants as metadata; Java 26.1 uses it.
type Properties []Property

type Property struct{ Key, Value string }

type StateRegistry interface {
    Intern(name string, props Properties) State
    Lookup(s State) (name string, props Properties, ok bool)
    Air() State
    Len() int
}
```

The registry is built once and frozen: `Intern` after `freeze()` on an unknown
identity is a programming error and panics with the name, because a lazily
minted handle would need a lock on the block write path, which is what this
milestone exists to avoid.

- [ ] **Step 3: Build the Java registries**

`NewJavaRegistry` walks `set.Blocks()`. For a version with `MinStateID == 0 &&
MaxStateID == 0` — which is how Java 1.8 leaves them — it interns one identity
per block per metadata value 0..15, with the metadata carried as the single
property `{"metadata", "N"}`. For a version with a state range it interns each
state in `MinStateID..MaxStateID` with the properties `data.BlockStates`
describes.

    MinY   int    // 0 on 1.8, -64 on 26.1

}

func (d Dimension) Sections() int          { return d.Height / 16 }
func (d Dimension) SectionIndex(y int) int { return (y - d.MinY) >> 4 }
func (d Dimension) Contains(y int) bool    { return y >= d.MinY && y < d.MinY+d.Height }

- [ ] **Step 3: Implement sections, chunks, and the builder**

func (s *Section) At(index int) State
func (s *Section) With(index int, state State) *Section
func (s *Section) WithMany(changes []Change) *Section
func (s *Section) IsAir(air State) bool          // for the section bitmap

type Chunk struct {

    Sections []*Section   // len == dim.Sections(); nil entry means all air
    Biomes   [256]Biome
    Gen      Generation
}

// Builder is mutable and is the only place a section is written in place.
// Generation is the one operation where that is correct, because nothing else
// can see the chunk yet.

- [ ] **Step 2: Implement**

```go
type World struct {
    dim    Dimension
    reg    StateRegistry
    gen    gen.Generator
    chunks sync.Map // ChunkPos -> *atomic.Pointer[Chunk]

    gen_counter atomic.Uint64 // the Generation stamped on every write

    // time and chests keep their mutex; they are not on the block path
    mu        sync.RWMutex
    chests    map[BlockPos]ChestContents
    age       int64
    timeOfDay int64
}

func (w *World) SetBlock(pos BlockPos, state State) bool {
    for {
        slot := w.chunkSlot(pos.ChunkPos())
        old := slot.Load()
        next, changed := old.with(w.dim, pos, state, w.gen_counter.Add(1))
        if !changed {
            return false
        }
        if slot.CompareAndSwap(old, next) {
            return true
        }
        // Lost the race: reload and rebuild from the winner's chunk. Rebuilding
        // from `old` here is how writes get lost.
    }
}
```

The comment on the retry is load-bearing and belongs in the code, not only in
this plan.

block path, they move into tile entities in M11.3, and converting them here

- [ ] **Step 2: Implement the adapter**

```go
type Adapter interface {
    Registry() StateRegistry
    EncodeChunk(c *Chunk) (protocol.Packet, error)
    EncodeUnload(pos ChunkPos) (protocol.Packet, error)
    EncodeState(s State) (int32, error)   // for BlockChange and MultiBlockChange
}
```

The 47 implementation resolves each handle to `id<<4|metadata` through a
`[]uint16` indexed by handle, built once from the registry, so the encode loop
is an array index rather than a map lookup.

- [ ] **Step 3: Memoize on the section pointer**

```go
// cache maps a section pointer to its encoded 8192 bytes. A section is
// immutable, so an entry can never be stale: a write produces a new pointer
// and the old entry becomes unreachable.
type cache struct {
    mu      sync.Mutex
    entries map[*Section][]byte
    order   []*Section  // bounded FIFO; see maxCachedSections
}
```

Bound it at `maxCachedSections = 4096`, which is 32 MB at 8 KB per section and
covers a 16-section column for 256 resident chunks. State the arithmetic in
the comment.

## Self-review notes

- **Task 7 is the risky one and it is last on purpose.** Everything before it
  is additive or mechanical, and each task leaves the tree green. Deleting the
  override map is the only step that changes which structure answers a
  question, and by the time it runs the model underneath it has been proved by
  the fixtures twice.
- **The golden generator test is written before the generators change and
  owned by M11.4 afterwards.** That is a deliberate hand-off: this milestone
  needs it as a safety net, and M11.4 needs it as a contract.
- **`extractOverrides` is knowingly expensive.** It is a diff against the
  generator for every resident chunk, and on a large pre-generated world it
  would be unacceptable as a permanent design. It lives for one milestone
  because the alternative is to bring M11.3's storage format forward into a
  milestone that is already rewriting the chunk model.
- **The 26.1 round-trip pulls a package into `vendor/` that nothing ships.**
  It is test-only, it adds about 700 KB of generated data to the vendor
  directory, and it is the only mechanism that proves the model is neutral
  before a second server exists. If the vendor cost is judged too high, the
  alternative is a build-tagged test that is not run by default, which is a
  test that will rot.
- **Nothing here makes the world tick faster.** The encode cache is the only
  performance change, and it is a side effect of immutability rather than the
  point. The point is that M11.3, M11.4, and M11.5 all become possible.
