> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> and skipped. The stores also live in `server/` rather than
> `internal/server/storage`, because they hand back public value types. The
> milestone record in `MASTER_PLAN.md` has the measurements and the rest.

**Goal:** Make the server read the world it writes. Anvil gains a reader, `overrides.json` and `chests.json` retire, saving becomes snapshot-driven and incremental, and the `Store` seam splits into three interfaces that name no internal type.

**Architecture:** `WorldStore` holds vanilla data in Anvil regions, `SideStore` holds everything vanilla has no field for, and `PlayerStore` holds per-player state as a public value type. All three are written from one `world.Snapshot` and stamped with its generation, so a mismatched pair is detected at load. The save path copies pointers on the tick goroutine and does every byte of work off it.

**Tech Stack:** Go 1.26.6 via `openserbia/go-flake`, Devbox, Task, `minecraft-protocol` v0.2.0, vendored dependencies.

- [x] **Step 1: Write the failing tests**

Mirror `writer_test.go` case for case — byte, int, long, float, double, byte

```go

```

- [x] **Step 2: Take the snapshot on the tick, do the work off it**

```go
func (s *Server) save(ctx context.Context) error {
    snap := s.world.Snapshot()   // the only part that touches the tick
    if err := s.worldStore.SaveSnapshot(ctx, snap); err != nil {
        return err
    }
    return s.sideStore.SaveSnapshot(ctx, snap, snap.Gen)
}
```

`saveAll`'s five sequential store calls collapse into this plus the player
loop.

- [x] **Step 3: Track the written generation per chunk**

The store keeps `map[ChunkPos]Generation` of what it last wrote and skips a
chunk whose generation has not moved. This map is the store's, not the world's:
a second store with its own idea of what it has written must not share state
with the first.

## Self-review notes

- **The migration is the only irreversible act in this milestone**, and it is
  arranged to be as reversible as a migration can be: it renames its inputs,
  it logs counts, and its test covers the case where the two disagree. If a
  reviewer wants one more safeguard, the honest one is a `-dry-run` flag on
  the vanilla example that runs the fold and reports without writing.
- **Task 2's vanilla fixture is a manual step in an otherwise automated
  plan.** There is no way around it: the only check that this reader handles
  real files is a real file, and this repository cannot generate one.
- **Chests move twice.** M11.2 leaves them on the world's mutex, and Task 6
  moves them into chunks. That is deliberate — moving them during a chunk-model
  rewrite would have entangled two changes — but it is two touches of the same
  code and worth naming rather than discovering.
- **`LoadChunk` erroring rather than regenerating is a behavior change with no
  test upstream of it.** Today a world with an unreadable region regenerates
  silently, because nothing reads regions. After this milestone the server
  refuses. That is the right answer and it will be the first thing someone
  reports as a regression, so the error message has to name the file.
- **Nothing here makes provenance possible on its own.** The sidecar container
  is written empty. It exists so M11.5 adds contents rather than a format.
