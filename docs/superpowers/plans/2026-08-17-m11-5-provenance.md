# M11.5 Provenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Status: partly complete, 2026-08-17.** Tasks 1, 2, 4, 5, 8, and 9 landed,
> together with Task 3's index, its tests, and the reconstruction test. Task 3
> Step 3 — routing the inventory click paths through the index — and Tasks 6
> and 7 did not. Until the click paths route through it an item's IDs go stale
> as soon as a player moves a stack, so the feature stays off; partial routing
> would produce false duplications rather than gaps, which is why it is all or
> nothing. The milestone record in `MASTER_PLAN.md` has the detail.

**Goal:** Give every item an identity that survives a restart, make the index that tracks it the write path so a duplication is caught where it happens, and record block and item history in an append-only log that answers three questions across restarts.

**Architecture:** An `ItemID` is a 24-bit persisted run epoch and a 40-bit counter. Every stack carries its IDs; every movement goes through `Index.Move`, which reports an ID that is live somewhere other than where the move says it came from. A `Recorder` takes typed records off the tick through a bounded queue and a writer goroutine drains it into a rotating file store. Block identity is sparse, chunk-keyed, in the sidecar M11.3 created empty. Everything is off by default.

**Tech Stack:** Go 1.26.6 via `openserbia/go-flake`, Devbox, Task, `minecraft-protocol` v0.2.0, vendored dependencies.

- [x] **Step 1: Write the failing tests**

```go

func TestTheEpochIsPersistedRatherThanDerivedFromTheClock(t *testing.T)

```

`TestTheEpochIsPersistedRatherThanDerivedFromTheClock` is the one that
enforces the design's reason: a clock that moves backwards mints colliding
IDs, and collision is the one failure that makes the whole structure
worthless. Assert that two `Minter`s built from the same stored epoch produce
the same first ID, and that the stored epoch advanced.

- [x] **Step 2: Implement**

```go
// ItemID identifies one item for the life of a server. The high 24 bits are
// the run epoch, persisted in level data and advanced once per start; the low
// 40 bits are a counter within that run.
//
// 24 bits is 16,777,215 starts: a server restarting every second exhausts it
// in six months. 40 bits is 1,099,511,627,775 items: minting a million a
// second exhausts it in twelve days. Both exits refuse to mint, log at error,
// and keep serving, because a server that will not start is worse than an
// audit gap.
type ItemID uint64

func (id ItemID) Epoch() uint32
func (id ItemID) Counter() uint64
```


- [x] **Step 2: Implement the index**

```go
type Index interface {
    Mint(n int, loc Location, by Actor) ([]ItemID, error)
    Move(ids []ItemID, from, to Location, by Actor) error
    Retire(ids []ItemID, at Location, by Actor) error
    Where(id ItemID) (Location, bool)
}
```

Backed by `map[ItemID]Location` under one mutex. It is the hottest structure
in this milestone and it is deliberately simple: a click moves at most 64 IDs,
and a sharded map is an optimization to reach for after M11.6 says it is
needed.

Default policy on `ErrDuplicate` is record and allow, because refusing turns a
duplication bug into item loss, and item loss on a false positive is worse for
the player. `ProvenanceDuplicateRefuses()` selects the other behavior.

- [ ] **Step 3: Convert the paths, one commit per file** — NOT DONE; see the status note.

Each conversion is the same shape: the code that already computes "this many
items left slot A for slot B" gains a `Move` beside it. Where the count

## Self-review notes

- **This is the largest sub-milestone by surface**, because `inventory.go`
  alone is 1,097 lines and every click path touches a stack. The
  one-file-per-commit ordering in Task 3 and the property test are the two
  things standing between it and a silent gap.
- **Task 3 Step 4 writes the reconstruction test before the conversion it
  covers.** That is deliberate: the detector should be proved against a known
  failure shape while the conversion is still in progress, not after
  everything already passes.
- **The default policy allows a detected duplication through.** A reviewer may
  reasonably want the opposite. The argument for allow is that a false
  positive under refuse destroys a player's items, and the detector is new
  code with no field history. Revisiting after a season of real use is the
  right time, not now.
- **The file store's queries are linear and the design says so.** If that is
  unacceptable, the answer is a different store implementation rather than an
  index bolted onto this one, and the interface is what makes that possible.
- **Two types become one in Task 2** — `player.Slot` and `world.ItemStack` —
  which is a refactor with no feature attached, done here because attaching
  identity to two types would guarantee they diverge.
- **The instrument has no open bug to prove itself against.** Both M3
  duplications are fixed. That is worth stating in the milestone record too,
  because a future reader will otherwise assume this milestone closed
  something.
