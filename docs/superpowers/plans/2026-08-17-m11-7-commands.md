# M11.7 Commands Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Status: complete, 2026-08-18.** All eight tasks landed. Four deviations are
> recorded in `MASTER_PLAN.md`: the built-ins are in package `server` rather
> than `server/commands/builtin` (import cycle), Tasks 2 and 4 landed as one
> commit (separating them needed a throwaway bridge), the parameter type list is
> eight rather than seven, and the vanilla list was derived from the 1.8 client
> language file rather than captured from a running server's `/help`.

**Goal:** Make a command a value an application can write, register, and test without a connection; declare each command's arguments once so execution, tab-complete, and brigadier rendering cannot disagree; and ship `vanilla.Stubs()` so the list of what a server still owes is visible.

**Architecture:** `Command` carries a `Signature` of overloads and typed parameters. The dispatcher parses against the signature and hands the handler an `Args`, so nothing re-parses. `Caller` replaces `*Connection`, so a command runs against a fake in a test. Completion is derived from the signature and rendered per version: a match list on protocol 47, a brigadier tree on 775.

**Tech Stack:** Go 1.26.6 via `openserbia/go-flake`, Devbox, Task, `minecraft-protocol` v0.2.0, vendored dependencies.

**Files:**

- [x] **Step 1: Write the failing tests**

```go
func TestAWordParamParses(t *testing.T)
func TestAnIntParamRejectsNonNumbers(t *testing.T)
func TestChoicesRejectAValueOutsideThem(t *testing.T)
func TestOverloadResolutionPicksByArity(t *testing.T)

func TestOptionalTrailingParamsResolve(t *testing.T)
func TestAMessageParamTakesTheRestOfTheLine(t *testing.T)
```

`TestAnAmbiguousArityErrorNamesBothShapes` is the `/tp` case: two arguments
match neither `<player>` nor `<x> <y> <z>`, and the error has to say what the
two shapes are rather than "usage: /tp".

`TestAMessageParamTakesTheRestOfTheLine` is `/say` and `/me`, which today take
`strings.Join(args, " ")`. A message parameter is greedy by definition and it
must be the last one in an overload; the parser rejects a signature where it is
not, at construction.

- [x] **Step 2: Implement**

```go
type ParamType string

const (
    ParamWord        ParamType = "word"
    ParamMessage     ParamType = "message"      // greedy, must be last
    ParamInt         ParamType = "int"
    ParamFloat       ParamType = "float"
    ParamPlayer      ParamType = "player"
    ParamCoordinates ParamType = "coordinates"  // one axis; three make a position
    ParamDuration    ParamType = "duration"     // /time's day|night|noon|midnight|N
)
```

Seven types, which covers all ten built-ins. The list is open for extension
and closed for improvisation: a command needing an eighth adds it here, where
Task 7's brigadier mapping will see it.

- [x] **Step 3: The caller and its message**

```go
type Message struct {
    Text  string
    Color string // "red", "gold", "" for the client's default
}
```

Deliberately small. Today's `sendSystemMsg` takes exactly a text and a color,
and inventing a rich text tree for a stub milestone would be designing 775's
text component format without a consumer.

- [x] **Step 4: Gate and commit**


## Self-review notes

- **Task 3 exists because the completion switch is undocumented behavior.**
  Sixty pinned cases written against code that is about to be deleted is
  tedious and it is the only way to know the rewrite kept its promises.
- **Task 5 Step 1 is manual and cannot be automated here.** Upstream has no
  1.8 command data. The plan says to capture it from a running vanilla server
  rather than from memory, and the header comment in the fixture is what makes
  it auditable later.
- **The `Message` type is deliberately thin.** Two fields, matching what
  `sendSystemMsg` already takes. A text component tree is what 775 wants and
  designing one here, with no 775 server, would be inventing a format against
  no consumer.
- **Brigadier rendering ships untested against a client**, and it is the one
  deliverable in this milestone that cannot be exercised end to end. It is
  included because the design's whole claim is that one signature produces both
  renderings, and a claim with no implementation is not a boundary.
- **Permissions default to allowing everything**, which will look like an
  oversight to anyone reading the code without the reason. The test name says
  it, the option's doc comment says it, and the milestone record should say it
  a third time.
- **This milestone can run in parallel with M11.2.** It touches the world only
  through three commands, and none of them depend on the chunk model. If both
  are in flight, the conflict surface is `server/options.go` and
  `server/server.go`, which is two files and worth naming in advance.
